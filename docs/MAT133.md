## 6. MAT133 template body builder

Module: `src/mat133/build_docx.py`

The builder starts from the cleaned MAT133 cover and appends its own body. It
does **not** read or clone any CSC662 sample question block.

Input models: `src/mat133/models.py`

- `Mat133Paper` — month/year, duration, questions, appendix.
- `Mat133Question` — number, common stem, parts.
- `Mat133Part` — label, question text, marks, optional diagram/formula,
  exact answer, mathematical `solution_latex`, optional `solution_marks`,
  marking notes and legacy `solution_steps` metadata.

Outputs:

- question paper DOCX and PDF;
- marking scheme DOCX and PDF in the original `NO | SOLUTION | MARK` table
  layout: line-by-line mathematical working, red `M1`/`A1`/`B1` codes and
  diagrams. Explanatory prose and numbered working steps are not rendered;
- optional one-page Appendix 1 formula sheet;
- marker-style cover (`INSTRUCTIONS TO MARKERS`, two scheme notes only),
  dynamic date/reference line, page-count line and body header;
- even/odd page headers and footer inheritance from the template;
- no horizontal rule under `QUESTION` headings, matching the reviewed
  group-1 question paper.

Validation functions check:

- DOCX/XML: parseable `word/document.xml`, crest present, no CSC662/legacy
  tokens, expected question headings for papers and part labels for schemes;
- PDF: cover on page 1, body starts page 2, all headings and marks present,
  no text beyond the right margin, no legacy tokens.

The builder was smoke-tested with 2, 10, 16 and 31-part papers. Current
validation outputs are in `outputs/mat133_gen_validation/`.

## 9. Planner, Library and publication

Planner: `src/mat133/planner.py`

- Five questions follow the structure observed in the 41 past papers:
  inequalities/absolute value; functions/coordinate geometry; complex
  numbers/algebra; systems/coordinate geometry; trigonometry/geometry.
- 15 parts and 64-72 marks per paper.
- Deterministic selection from the 57 generators with a seeded RNG; across
  seeds 1-20 every generator is used.
- No API key, no LLM call and no cost.

Library: `src/mat133/library.py`

```bash
uv run python -m src.app.prebuild_library --seeds 1-20 --subject MAT133
```

Each seed writes `paper.docx`, `paper.pdf`, `scheme.docx`, `scheme.pdf` and a
`meta.json` under `outputs/web_cache/MAT133/<config-hash>/`. The build rejects
a missing crest, missing cover, missing part labels/marks, invalid XML,
forbidden CSC662 tokens, or right-margin overflow.

MAT133 metadata explicitly carries `total_marks` (64-72),
`has_practice_mode: false` and `has_placeholders: false`. The Library uses
those flags to show **Total marks** instead of **Computed marks**, renders
placeholders as **—**, and filters by total marks. CSC662 keeps computed
marks and numeric placeholders.

Publication:

- `scripts/build_public_bundle.py` builds all available subjects by default.
- `outputs/public_bundle/mat133/` contains the public pages; `library/MAT133/`
  contains 20 papers and 20 schemes in DOCX/PDF.
- MAT133 public schemes do not need the CSC662 quote-omission marker because
  they contain no lecture quotes.
- The Worker route map and gallery share validation accept MAT133.
- R2 upload state and quota ledger are in `outputs/`.

## 10. Known limits

- OCR-damaged scanned papers produce low-confidence rows; these are flagged,
  not silently corrected.
- Some older papers print one mark after a group of subparts; the extractor may
  repeat that group mark, so mark totals on those papers are indicative.
- Trigonometric identities use a small set of verified templates; the
  generator checks each identity with SymPy before returning it.
- Scheme formulas are LaTeX source (`answer_latex` / `solution_latex`) rendered
  to PNG and embedded in the DOCX; native Word OMML equations are not used.
- The renderer ignores `solution_steps`; they remain only as legacy metadata.
  All visible working comes from `solution_latex` and `answer_latex`.
- Geometry figures are schematic and not drawn to scale.
- The R2 `shared/` lifecycle rule still needs `Workers R2 Storage Write` or a
  dashboard rule; the Worker Cron remains the functional expiry path.
